# UI 0.2.0 — proposed release

Status: unpublished; publication is held. This proposal prepares
`@marquee-ui/ui@0.2.0` with the existing published `@marquee-ui/tokens@0.1.0`.
The current public UI release is 0.1.10. Do not use an npm install command for
0.2.0 until publication is verified.

## Release notes

- Add Select, Tabs, Dialog, AlertDialog, Popover, Tooltip, DropdownMenu, Slider,
  Combobox, Calendar, DatePicker, Table, DataTable and Chart: 35 families total,
  distributed as 36 registry items including `utils`.
- Preserve explicit parts, caller-owned state and token roles. DataTable uses a
  caller-created reactive TanStack Table 9 instance; Chart composes Recharts 3
  primitives. The [recipe contracts](../recipe-contracts.md) describe their bounds.
- Document all family contracts, deliberate common-name API differences and
  the [remaining catalog/API work](../component-parity.md). Full shadcn parity
  is not claimed.
- Strengthen regression checks for story-play execution and Chart SVG focus.
  Keep the measured isolated browser and external consumer proofs.

This is a pre-1.0 minor release for the expanded component surface. The token
roles, emitted CSS/JSON and fonts need no release: all 32 files in the published
tokens tarball are byte-identical to their current packed counterparts. The only
additional local packed file is an internal docs-theme preset source; it is not
an exported runtime dependency of the component recipes. Use the published token
package, not a differently packed artifact bearing the same version.

## Install the proposed artifact locally

Use the Node 22 / React 19 / Tailwind 4 stack in [getting started](../getting-started.md).
From the reviewed checkout, create the UI tarball without publishing:

```sh
MARQUEE_ARTIFACTS="$(mktemp -d)"
pnpm --dir packages/ui pack --pack-destination "$MARQUEE_ARTIFACTS"
```

Copy `examples/consumer` outside the pnpm workspace and work in that copy:

```sh
npm ci
npm install --save-exact "$MARQUEE_ARTIFACTS/marquee-ui-ui-0.2.0.tgz"
```

Serve the registry from that installed artifact in one terminal:

```sh
CONSUMER_REGISTRY_PORT=4186 npm run registry
```

Set the consumer's `components.json` mapping to
`"@marquee": "http://127.0.0.1:4186/{name}.json"`, then add the desired parts:

```sh
npx shadcn@4.21.4 add @marquee/data-table @marquee/chart --yes
npm run build
```

The installed registry keeps component source and dependency declarations tied
to this tarball. Import the copied components through the app's `@/components/ui`
alias. The UI package's source export is not a precompiled JavaScript bundle.
The cold release-candidate proof and exact artifact hashes are recorded in
[RELEASE-READINESS-1](../batches/RELEASE-READINESS-1.md).
